# Reading Lens Constitution

## 1. 製品の目的
Reading Lensは速読アプリではない。不要な認知負荷を減らし、視線と思考が自然に文章を追える環境を作る。

## 2. 変更してはいけない原則
1. 視線は誘導するが、強制しない。
2. 読む速度より理解できる速度を優先する。
3. ユーザーはいつでも止まり、戻り、飛ばし、速度を変更できる。
4. UIは目立たず、操作より読書体験を前面に置く。
5. 情報を減らしても、理解を壊すほど文章を断片化しない。
6. アルゴリズム上の正しさより、身体感覚と実際の使用経験を重視する。
7. AIはユーザーの意思を上書きしない。
8. 中心思想や操作原則の変更にはユーザーの明示的承認を必要とする。
9. 機能追加より「圧迫感が減るか」「視線が自然か」の検証を優先する。
10. Lensを追いかけなければならない感覚が生じた場合、その設計は失敗として扱う。

## 3. HTML Reading Browserとの分離
Reading LensはHTML Reading Browserとは別の製品、GitHubリポジトリ、コードベースとして管理する。

- HTML Reading Browser：文章を取り込み、構造を理解し、表示方法を再構成する。
- Reading Lens：既に表示されている画面の上に透明レイヤーを重ね、見え方を変える。

コードの安易な統合は行わない。共通化は用語、設計思想、設定形式など必要最小限に留める。

## 4. 開発原則
各開発サイクルでは、一つの仮説を定め、必要最小限の実装を行い、実使用の感想を記録してから次へ進む。
OCR、AI解析、複雑な画面認識は初期段階の必須要件にしない。
